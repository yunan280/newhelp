### 翻车与返工

**1. `.env` 连续两次"说填了但没填"——两次都靠实测发现,没靠自述**

- 第一次:用户选 A 说"我已经填好了"。我 `test -f .env` 一查——**文件根本不存在**;`git status` 干净,`.env.example` 大小和时间戳(11:48)都没变,说明编辑器里改了没存盘,或者改的是 `.env.example` 而不是新建 `.env`
- 第二次:我把 `.env` 从模板生成好(预填 DeepSeek 的 `base_url` 和 `model`),用户再次说"好了"。我再查 —— **key 那行仍是占位符 `sk-xxxxxxxxxxxxxxxx`**
- **教训**:用户自述的状态必须用命令复核。写进流程:涉及"用户说他配好了"的环境变量,一律先断言再往下走
- **附带收获**:确认 `.env` 被 `.gitignore:4` 挡住,`git check-ignore -v` 可验证;worktree 是独立工作区,**`.env` 不会自动跟过去**,需要单独复制

**2. 骨架依赖 pin 落后一整代(规划期发现,未造成返工)**

实测 PyPI 当前版本 vs 骨架 `pyproject.toml`:

| 包 | 骨架 pin | 实际当前 | 差距 |
|---|---|---|---|
| `langchain` | `>=0.3` | **1.4.2** | 跨大版本 |
| `langchain-openai` | `>=0.2` | **1.6.6** | 跨大版本 |
| `fastapi` | `>=0.115` | **0.141.1** | 差 26 个小版本 |

骨架是按 LangChain 0.x 的思路写的。`>=` 虽然仍能装上 1.x,但**代码写法会完全不同**。若不是先查 Context7,这里必返工。

**3. FastAPI 已有原生 SSE,我的记忆里没有**

Context7 查到 `fastapi.sse.EventSourceResponse` + `ServerSentEvent` —— 原生 SSE 支持,支持 POST 且 `data=dict` 自动序列化。按记忆会写成手拼 `StreamingResponse(media_type="text/event-stream")`,虽然也能跑,但等于放着官方 API 不用。已列为**待验证项**:该 API 较新,装完依赖立刻验证真存在,不成立则退回手写并回报。

**4. 我推翻了自己的依赖提议(tiktoken)**

第 3 节设计里我提议引 `tiktoken` 算 token。查 `trim_messages` 文档时发现官方配了 `count_tokens_approximately`,零额外依赖 —— 当场划掉 tiktoken,并在设计里写明代价(中文会低估)和为什么不影响本章(预算 2048 ≪ DeepSeek 128K 窗口)。

**自己提的方案自己改**这件事本身值得记:差点为了"看起来更专业"多引一个依赖。

## 2026-10-07 · 官方接口与版本边界核对

**用户关键原话**：「MCP Server：用 MCP 官方 Python SDK 自建，走 Streamable HTTP」「MCP Client：用 LangChain 官方 langchain-mcp-adapters 的 MultiServerMCPClient 多 Server 接入」。

**关键产出**：先用 Context7 查 MCP SDK、langchain-mcp-adapters、LangGraph、jsonschema、SQLAlchemy、FastAPI。再读取 adapters 官方源码确认：`get_tools(server_name=...)` 可逐 Server 动态发现，工具调用时创建新 session；当前 adapters 依赖 `mcp>=1.24,<2`，SDK 最新主线为 2.x，官方维护线 1.x 支持 FastMCP 和 Streamable HTTP。设计保留两项既定选型，使用适配器支持的官方 SDK 1.x，实施时锁定兼容发行版本。MCP `args_schema` 可为 JSON Schema 字典，不能继续统一调用 `.model_validate()`；LangGraph resume 会从中断节点开头重放，确认节点须与已完成工具副作用分开。

**用户拒绝或纠偏**：无新增；未替换 MCP 官方 SDK、MultiServerMCPClient、Streamable HTTP 或 LangGraph。

**翻车与返工**：Context7 返回的 SDK 主线示例包含 2.x 的 `MCPServer`，进一步查 1.x 文档与官方依赖声明后避免混用。代码现状探索时猜测的两个 ticket 模块文件名不存在，已通过文件清单定位真实 `ch05/actions.py`，未据猜测修改代码。

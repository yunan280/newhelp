# Ch07 开发过程：当前会话上下文管理

## 2026-10-04 · 项目与接口核对完成，进入架构设计

**用户关键原话**：「我要用 Superpowers 模式让客服在一通会话里记得住前面聊过什么」「只管当前会话，不跨会话、不存用户画像」「上面点名的技术选型是定死的」「不许收尾时一次性补记」。验收要求包括默认二十轮无压缩，以及 18000 窗口配置出现降级、异步摘要和最早订单指代恢复。

**关键产出**：使用 Superpowers `using-superpowers`、`brainstorming`，按架构级任务推进。实际工作目录为 `ch02-tools`，分支 `ch02-tools`，开始时工作树干净，基线提交 `0107c00`。只读核对确认已有 `WorkflowState.messages` 的 `add_messages` reducer、官方 SQLite checkpoint、MySQL 原文消息账本；主力 Agent 仍使用固定 2048 历史裁剪，指代历史另用最近 20 条/单条 2000 字，工具原文仍写 messages；动态证据/控制信息还追加为 system。前端已有 user_id 与 session_id、单会话本地历史及 Ch06 等待订单恢复，需要接入多会话列表并保持中断恢复行为。

接口查证先使用 Context7 MCP：LangGraph 图接口与持久化、LangChain `trim_messages`/`bind_tools`、SQLAlchemy 事务/行锁/Session 并发边界、FastAPI lifespan/后台任务/GET 参数及返回模型。随后在既有 `.venv-ch03` 只读检查安装版本与签名：LangGraph 1.2.12、checkpoint-sqlite 3.1.1、langchain-core 1.6.5、langchain-openai 1.6.6、FastAPI 0.141.1、SQLAlchemy 2.1.1。没有修改应用代码、数据库、依赖、共享 .env，也没有调用真实聊天模型。

**用户拒绝或纠偏**：本阶段没有新用户答复或纠偏。已提出预算口径澄清：现仓没有 5650 的推导公式或默认 X/Y；不能把 64000 的单轮累计调用预算误当模型上下文窗口。保留指定框架与现有单实例 checkpoint，不自行更换持久化方案。

**翻车与返工**：首次版本探测误用了早期 `.venv`，其中没有 LangGraph；按 README 指向 `.venv-ch03` 后查证成功。首次搜索假定有顶层 templates/static 与 `ch06/service.py`，实际静态页在 `src/mewhelp/static`，Ch06 复用 Ch05 service；只读探索已纠正。发现 Ch06 指代来源校验依赖消息 ID，摘要不能只注入正文而不补来源，否则最早订单验收会失败。预算还有并行工具峰值与校准哈希两个必须显式设计的接缝。

本阶段仅是探索完成；brainstorm 尚未定稿，书面设计及计划尚未获批，不把这些门槛追记为通过。

## 2026-10-04 · 用户 DDL 纳入设计，书面草案与自审完成

**用户关键原话**：「一段投影用的摘要，和摘要覆盖到哪条的锚点」「两个文件都要 apply」「summary_upto < id ≤ layer1_from 层 2」「一段一行、只追加」。对预算澄清的答复为「没有现成公式，请给出可审查的标定方案」。

**关键产出**：草案 `docs/superpowers/specs/2026-10-04-ch07-context-management-design.md`，含权威 DDL 映射、两步迁移/重跑契约、完整 State 与 MySQL 可见原文的职责、工具来源/配对、纯投影、异步区间快照和事务、真实上下文日志、只读 API/会话切换、标注评估和实际 22 轮验收。初始工程预算包明确公开：prefix 1350、每条证据 400、摘要 500、安全 500、控制结构 400；演示固定开销 6350、峰值 6000，得到历史 5650。整数 70/30 分配额外留 1 token 拼接余量，得到 3954/1695。标定不是已完成测量；文档要求真实 usage 联合校准预算与中文 token 口径。

自审核对：边界统一为用户后续 DDL 的闭区间；后台覆盖只能追到触发时的 L 快照，不能把并发新增内容标为已摘要；summary 列只重建拼接投影，段原文不重写；模型背景不单独占 system；前台与后台不共享 Session；64000 的累计调用预算与模型窗口分别校验；原 Ch06 校准哈希不能被上下文改动静默绕过。文档无占位章节。尚需用户审核明确提案：steps 按整轮工具调用总量计（并行也占名额）、500 token 的最近连续摘要段投影，以及 checkpoint 保留工具原文/MySQL 只回载可见原文。

**用户拒绝或纠偏**：追加 DDL 把 `layer1_from_msg_id` 明确定义为层 1 之前的截止 ID，而非原文需求可能读作「这条起含自身」；按后续 DDL 纠正。summary 列允许最近段的拼接投影，但段表仍是权威。用户授权提出标定方案，没有授权把初始参数声称为实测安全值，也尚未批准本次书面设计/实施计划。

**翻车与返工**：没有产品实现返工。本阶段避免了三项潜在返工：步骤数不能漏掉并行工具峰值；5650×70% 的数学结果是 3955，采用显式 1 token 拼接余量复现用户要求的 3954，而不是依赖 float 向下取整偶然误差；有限最近段投影可能淘汰最早事实，文档公开其范围并要求 22 轮订单验收时证明首段仍被注入，不假装有无限长期记忆。纯中文/混排初步只读计数显示当前 Agent system+tool schema 约 668 token（CJK1/ASCII4 起始口径），只作 prefix 工程预留的背景，未调用模型、未验证最终预算包。

此阶段是草案与自审完成，**不是 brainstorm 定稿**。按已读 Superpowers brainstorming 的架构级门槛，等待用户审阅书面 spec 后才写实施计划；当前只有两份设计/过程文档，未应用用户 DDL、未启动验收或提交代码。

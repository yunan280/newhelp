# Ch06 正式分流器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让现有聊天页每轮正确理解并分流问题，以可恢复的订单点选和强制政策检索处理本单退款/售后，并保存用户明确提交的退款申请。

**Architecture:** 在既有 Ch05 StateGraph 中增加 Query 理解、固定订单/政策节点及官方 interrupt/resume，不建立第二套聊天编排。一般 FAQ 保持单次检索，具体订单诉求先拿事实再进入主力 Agent；检索侧扩写合并候选。Prompt 以冻结标注评估验证，后端控制代码 TDD，前端直接 Vibe Coding 与真实浏览器检查。

**Tech Stack:** 现有 FastAPI 0.141.1、SQLAlchemy 2.1.1/MySQL、LangGraph 1.2.12、AsyncSqliteSaver 3.1.1、LangChain core 1.6.5/openai 1.6.6、PyMilvus 2.6.17、Pydantic 2.13.5、原生 HTML/CSS/JavaScript。

**Spec:** `docs/superpowers/specs/2026-10-02-ch06-router-design.md`，用户 2026-10-02 明确确认，设计提交 `7098af5`。用户已确认本计划并选择 Native：当前会话逐项实现，最后独立审查后端。

## Global Constraints

- 项目根 `C:/Users/27497/projects/mewhelp-wt/ch02-tools`；复用现有 linked worktree/分支，不改变外层 main，不自动 push/merge。
- 一般 FAQ 单次检索、不索要订单、不扩写；具体订单退款/售后按「拿订单 → 扩写 → 政策检索 → Agent」。
- 分类 JSON 只有 `intent`、`confidence`；八类为物流、订单、商品咨询、退款退货、售后、投诉、闲聊、其他。confidence 必须有限且在 0～1。
- 已完整、指代明确的问题原样透传；同 session 历史用于消解，不做跨会话记忆，不猜订单、不追问退款原因。
- 扩写 JSON 只有 `queries`，2～4 条非空、不同侧重点的查询；主查询也检索，知识不因扩写入库多份；最终证据最多 10 条。
- 同一上游/凭据，默认意图主模型 `deepseek-v4-pro`；成本降级默认关闭，低成本模型低置信度只升级一次。模型或固定选型走不通，说明并问用户。
- 不升级依赖或增加外部组件；具体库/API 动手前使用 Context7 官方文档并核对实际版本/签名。可复用 spec 第 12 节已查的同一接口；新接口必须再查。
- 保留既有 64000 模型 token、180 秒单执行窗口、30 秒单请求、4 次 Agent 决策/8 次工具限制；等待点选释放连接与锁，恢复只刷新执行时钟，不清零累计用量。
- 订单是固定且有 demo 用户归属的演示数据；退款只保存本地 pending 申请，明确提交前不写，不能声称已批准/到账。
- 固定退款原因：七天无理由、商品质量问题、与描述不符、破损或缺件、发错货、其他；初始为空，用户必选。

## Review Focus

1. 两个订单后说“它”、或退款后切回物流：不臆定订单、不继承旧意图/证据；Task 3/8 测试覆盖。
2. 点选与新消息并发、旧卡片重发：只一个活跃选择，改问取消旧流程；Task 7 测试覆盖。
3. 等待超过 180 秒、进程重启和恢复中断：保留原问题/累计用量，恢复不重跑分类、不重复账本；Task 7/8 测试覆盖。

## 执行方式与评审

推荐 **Native**：由当前主代理按任务顺序实现，后端每任务 TDD/评估留痕，最后一次独立整分支后端 review。任务共享 State/DTO/模型预算/同一图的接口较多，顺序执行能减少分散上下文和重复评审成本。

也可选 **Subagent-driven**：按任务派实现子代理与独立审查；前端任务仍免 brainstorm/TDD/code review，不因执行方式改动用户例外。无论选哪种，均须用户先审阅本计划并明确执行方式，然后才进入实现技能。
